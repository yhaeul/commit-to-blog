# plan-next

다음 구현 섹션을 커밋 단위로 계획하고, 세부 체크리스트를 `docs/checklist.md`에 삽입한다.
구현은 하지 않는다 — 계획과 삽입까지만 담당한다.

## 실행 순서

1. `docs/checklist.md`를 읽어 미완료(`- [ ]`) 항목이 있는 섹션 중 **가장 앞선 섹션**을 찾는다.
   - 섹션 내 항목이 모두 완료(`- [x]`)이면 다음 섹션으로 넘어간다.
   - 최상위 항목 아래에 이미 들여쓰기된 세부 항목(`  - [ ]` 또는 `  - [x]`)이 있으면, 해당 섹션은 이미 계획된 것이므로 건너뛴다.

2. `docs/architecture.md`와 `docs/interactions.md`를 읽어 해당 섹션의 설계 내용을 파악한다.

3. 해당 섹션의 미완료 항목들을 **커밋 단위**로 묶는다.
   - 하나의 커밋은 독립적으로 빌드 가능한 최소 단위여야 한다.
   - 연관된 파일 변경이 한 커밋에 모이도록 묶는다.
   - 커밋 수는 섹션 규모에 따라 1~5개 정도가 적절하다.

4. 각 커밋에 대한 세부 체크리스트를 작성한다. 각 항목은:
   - 구체적인 파일 경로나 함수명을 포함한다.
   - `docs/architecture.md`의 설계 내용을 반영한다.
   - CLAUDE.md의 Key Patterns에 명시된 패턴(싱글톤, SSR 처리 등)을 반영한다.

5. 작성한 세부 체크리스트를 **사용자에게 먼저 출력**한다. 파일에는 아직 쓰지 않는다.
   - 아래 출력 형식 예시를 따른다.
   - 출력 후 "이 내용으로 `docs/checklist.md`에 삽입할까요?" 라고 묻는다.

6. 사용자가 확인하면 `docs/checklist.md`에 삽입한다.
   - 각 최상위 항목(`- [ ] ...`) 바로 아래에 해당 커밋의 세부 항목을 들여쓰기(`  - [ ]`)로 추가한다.
   - 기존 텍스트는 절대 수정하거나 삭제하지 않는다. 세부 항목만 추가한다.
   - 삽입 완료 후 "`/implement-next`로 첫 번째 커밋을 시작할 수 있습니다." 라고 안내한다.

## 출력 형식 예시

```
## 📋 다음 작업: 섹션 2 — 데이터 레이어

### MongoDB 연결 싱글톤
- [ ] `src/lib/mongodb.ts` 생성
- [ ] `MongooseCache` 인터페이스 정의 (`conn`, `promise` 필드)
- [ ] `declare global { var mongoose: MongooseCache }` 타입 선언
- [ ] `connectDB()` 함수 구현 — `global.mongoose` 캐싱 패턴

### Post 모델
- [ ] `src/models/Post.ts` 생성
- [ ] `IPost` 인터페이스 정의 (architecture.md Data Model 기준)
- [ ] Mongoose 스키마 및 모델 export — 중복 등록 방지 패턴

이 내용으로 docs/checklist.md에 삽입할까요?
```

## 주의사항

- 설계와 다른 방향으로 계획하지 않는다. 설계 변경이 필요하면 사용자에게 먼저 알린다.
- 커밋 번호는 체크리스트에 포함하지 않는다.
